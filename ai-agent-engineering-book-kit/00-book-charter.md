# 00｜全书立项说明（Book Charter）

## 1. 书名

《AI Agent 系统架构与工程实践：从模型原理到企业级 AI 基础设施与机器人智能》

## 2. 核心定位

面向具备软件工程、后端开发和系统架构经验的读者，系统学习模型、Agent、RAG、数据工程、推理服务、评测、安全、分布式执行、边缘智能与机器人 AI。

本书不是某个框架的入门手册，而是围绕工程问题建立可迁移的技术判断能力。

## 3. 读者画像

- 能理解 API、数据库、微服务、容器和基本分布式系统；
- 不要求具备机器学习研究背景；
- 默认采用“先白话解释，再给严格定义，再讲原理和实现”的教学方式；
- 专业术语首次出现时给出中英文名称、直观解释和准确边界。

## 4. 学习终点

读者应能：
1. 解释 LLM 从 Token 输入到生成输出的主要过程；
2. 独立实现基础 Agent Loop 和工具调用；
3. 设计 Runtime、Harness、Workflow 和多 Agent 协作；
4. 构建 RAG 与多模态检索流水线；
5. 设计微调、推理部署和模型路由方案；
6. 建立 Agent Evaluation、Trace、Replay 和回归测试体系；
7. 设计安全、权限、沙箱和持久化执行；
8. 处理时序数据、工业异常检测和机器人数据；
9. 设计边云协同和机器人智能诊断系统。

## 5. 全书结构

- Part I：AI 与 Agent 基础架构
- Part II：模型工程与推理系统
- Part III：RAG 与 AI 数据工程
- Part IV：Agent 工程化与治理
- Part V：分布式 AI 与机器人智能
- Part VI：综合架构设计与工程实践

## 6. 内容深度

每章按以下层次递进：
- L1 概念：是什么、为什么需要；
- L2 原理：内部如何工作；
- L3 实现：代码、数据结构、流程；
- L4 工程：部署、故障、性能、安全、成本；
- L5 判断：适用边界、方案对比、设计取舍。

## 7. 重要技术边界

- RAG 解决外部知识获取，不等于模型训练。
- Fine-tuning 改变模型参数，不等于把实时业务数据“塞进模型”。
- Agent Evaluation 不只评最终答案，也要评执行轨迹和工具行为。
- Durable Execution 解决长任务可靠执行，不等于普通状态机。
- 时序异常检测不必然需要 LLM；传统统计和机器学习可能更合适。
- 边缘 AI 的模型选择必须考虑设备芯片、算子支持、内存、功耗、时延和升级机制。
- LLM 不应直接替代机器人底层实时控制、安全联锁和确定性控制系统。

## 8. 编写原则

结论先行、白话解释、技术定义准确、图表优先、代码可运行、数据可复现、来源可追踪。
