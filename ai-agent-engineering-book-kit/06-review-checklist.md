# 06｜章节质量门禁（Review Checklist）

## A. 技术准确性
- [ ] 关键术语定义准确，未混淆相邻概念。
- [ ] 算法、公式、流程与原始资料一致。
- [ ] 区分标准规范、框架实现和作者建议。
- [ ] 未虚构内部架构、性能数据或厂商实践。
- [ ] 对版本敏感内容注明版本和核验日期。

## B. 教学质量
- [ ] 先说明问题，再讲概念和原理。
- [ ] 术语首次出现有中文解释和准确技术定义。
- [ ] 有至少一个真实工程场景。
- [ ] 有正例、反例和常见误区。
- [ ] 读者能理解技术的适用边界。

## C. 架构与图表
- [ ] 架构图模块职责清楚。
- [ ] 流程图与正文一致。
- [ ] 时序图标明参与者和调用方向。
- [ ] 图中没有无解释缩写。
- [ ] Mermaid 源码可渲染。

## D. 代码与实验
- [ ] 代码已运行，或明确标注未验证。
- [ ] 环境、依赖和版本明确。
- [ ] 安装与运行步骤可复现。
- [ ] 正常路径和失败路径均有测试。
- [ ] 实验结果有数据和环境说明。
- [ ] Demo 与生产级实现边界清楚。

## E. 工程完整性
- [ ] 讨论性能、成本和安全。
- [ ] 讨论超时、重试、故障恢复（适用时）。
- [ ] 说明监控和运维方式。
- [ ] 方案对比有明确选择依据。
- [ ] 给出可量化验收标准。

## F. 引用与许可证
- [ ] 关键事实有来源。
- [ ] 引用未超出合理范围。
- [ ] 代码和图表遵守来源许可证。
- [ ] 第三方内容未被伪装成原创。
- [ ] 参考链接可访问。

## 严重级别
- Blocker：核心事实错误、代码不可用却声称可运行、侵犯许可、严重安全误导。
- Major：关键知识缺失、核心图表错误、实验不可复现、技术边界错误。
- Minor：解释不清、次要遗漏、术语格式不统一。
- Suggestion：可读性、案例、图表或扩展方向建议。

## 完成条件
所有 Blocker 和 Major 关闭；核心实践可复现；参考资料可追踪；Editor-in-Chief 批准。
