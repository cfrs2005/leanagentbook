## 环境与命令

主环境：macOS / arm64，Python 3.15.2，SQLite 3.54.1。另用本机 Python 3.12.14 / SQLite 3.53.1 运行相同测试，核对较低版本兼容性。最低声明版本 3.11 未在本机实测，代码仅使用 3.11 已有的标准库 API。

```sh
python3 -m unittest discover -s labs/durable_execution -p 'test_*.py' -v
python3.12 -m unittest discover -s labs/durable_execution -p 'test_*.py' -v
python3 scripts/check_book.py
```

两套环境均通过 29 项测试：Python 3.15.2 耗时 7.271 秒；Python 3.12.14 耗时 7.031 秒。时间只用于记录本次执行，不是性能目标。

## 独立 CLI 复现记录

除 unittest 中的 CLI 调用外，另用临时数据库运行[实验说明](README.md)中的入队、重复投递、崩溃、恢复、重试耗尽和补偿命令；每次检查退出码，并解析 JSON。

```text
ENQUEUE {'inserted': True}
DUPLICATE {'inserted': False}
CRASH running 0 1
RESTART {'attempts_handled': 1}
RECOVERED succeeded 3 2 3 30
DEDUP 1
RETRY dlq 2
COMPENSATED cancelled 1 1 0
```

`CRASH` 依次为状态、检查点、效果条数；故障进程实际退出码为 73。
`RECOVERED` 依次为状态、检查点、尝试数、效果条数、金额合计。
`COMPENSATED` 依次为状态、效果条数、反向条数、净额。重复补偿仍只有一条反向记录。

## 自动测试范围

QueueTests 使用虚拟时间，但不模拟存储与授权判断。ProcessTests 使用真实时钟和进程；`os._exit()` 在故障位置直接退出，未用抛异常冒充崩溃。

四个窗口都要求恢复后状态成功、尝试数为 2、效果条数为 3、金额总和为 30。未提交事务必须没有效果；已提交效果但未写检查点时必须出现去重事件。独立接收端在提交后、客户端回执前退出 74；重放有键模式为一笔 10，无键模式为两笔 20。
